    post

    • post(
          body: Create_trigger_request,
          requestConfiguration?: RequestConfiguration<object>,
      ): Promise<undefined | Create_trigger_response>

      Validation is synchronous, so a mistake is a 400/409 at creation, not a silent miss at the firstfire. Exactly one of webhook / cron must be present and match kind. kind=cron forbids awebhook block and requires a parseable cron.cron_expr and a valid IANA cron.timezone.session_mode=fresh requires session_template (a well-formed agents.yaml Agent manifest) andforbids bound_session_id; session_mode=reuse requires bound_session_id (an existing team-ownedsession) and forbids session_template. output.mode selects the destination block (email/slack),which is stored encrypted. name must be unique per team among non-deleted triggers.For webhook triggers the response includes webhook_secret exactly ONCE - it is never returnedagain. Cron triggers return no secret and carry a computed trigger.cron.next_run_at. The team anduser identity are taken from the authenticated principal, never the body.
