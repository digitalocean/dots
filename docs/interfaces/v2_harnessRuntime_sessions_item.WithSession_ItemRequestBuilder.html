    patch

    • patch(
          body: Patch_session_request,
          requestConfiguration?: RequestConfiguration<object>,
      ): Promise<undefined | Patch_session_response>

      Updates the settings of an existing session. Changes apply to this session only; the agentconfig the session was created from is not modified.Each request makes one of two kinds of update, and the two can't be combined:- Session preferences: set resume_on_topoff. Applied immediately; returns 200.- Session settings: set manifest_yaml to a partial manifest that holds only the sections to change. Applied in the background; returns 202.An empty body ({}) returns 400.### Updatable session settings| Section | What it changes | Agent restart || --- | --- | --- || tools | The session's Action Gateway tools (do.actions entries). Custom MCP servers can't be changed. | No || env | Environment variables (name and value). | Yes || env.HARNESS_INFERENCE_MODEL | The model, for sessions that use DigitalOcean Serverless Inference. | Yes || env.MODEL, env.OPENAI_MODEL, env.ANTHROPIC_MODEL | The model, for sessions that use their own OpenAI-compatible or Anthropic endpoint. | Yes || secrets | Plain secrets (name and value). | Yes || secrets (URL-bound) | URL-bound secrets: value, url, and scheme. | No || secrets (OAuth) | The provider connection an OAuth secret uses (actor). | Yes || egress | The hosts and IP addresses the session can reach (allow_hosts and allow_ips). | No |Sections you omit are not changed. Each section you include replaces that section in full; seemanifest_yaml for the exact rules.### Changing the modelYou change a session's model through env; a top-level model section returns 400. The keyto set depends on the model endpoint the session was created with:| Session created with | Model endpoint | env key that sets the model || --- | --- | --- || HARNESS_INFERENCE_MODEL, and none of the keys below | DigitalOcean Serverless Inference | HARNESS_INFERENCE_MODEL || OPENAI_BASE_URL | Your OpenAI-compatible endpoint | MODEL, or OPENAI_MODEL || ANTHROPIC_BASE_URL, or an ANTHROPIC_API_KEY secret | Your Anthropic endpoint, or the Anthropic API | ANTHROPIC_MODEL, or MODEL |A session keeps the model endpoint it was created with. Its provider and base URL can't bechanged (422). The provider API key (OPENAI_API_KEY or ANTHROPIC_API_KEY) can be rotatedbut not added, removed, or moved to another URL or scheme (422). See manifest_yaml for therules.The following can't be changed on an existing session: custom MCP servers (422), the egressVPC (vpc_uuid and subnet_uuid, 422), platform-managed model keys, and permissions(400). To use a different custom MCP server or VPC, create a new session.### Switching an OAuth connectionAn OAuth secret that names a provider connection with actor can move to another connection ofthe same provider while the session runs. actor is the connection's user_id; seeGET /v2/harness-runtime/auth/{provider}/connections.Send the secret with source, provider, and the new actor, and keep every other secret as{}. See manifest_yaml for an example.The platform first checks that you can use the new connection: it must be active, and eitheryours or shared with your team (400 otherwise). Switching back to the connection the agentconfig names skips this check, so any team member can do it. The platform then gives the sessionthat connection's token and restarts the agent, so the next git operation uses the newconnection. Sending the connection the secret already uses returns 200 with outcome set toUNCHANGED.The switch applies to this session only:- New sessions from the same agent config still start on the connection the config names.- A rollback, or a fork from a checkpoint, uses the connection the session had when the checkpoint was taken.- The switch changes only the token in the session. Action Gateway tools (do.actions entries) keep using the connection Action Gateway picks for the session, so git and those tools can act as different accounts.- A token the agent already read stays valid with the provider until the old connection is revoked.Switching OAuth connections must be enabled for your team (403 otherwise). The followingstill require a new session (422): adding or removing an OAuth secret, changing its provider,and switching an OAuth secret that was created without actor.### URL-bound secrets and egressURL-bound secret and egress changes take effect on the session's next outbound connection.An update that changes only URL-bound secrets and egress doesn't restart the agent and ends inAPPLIED. Connections that are already open stay open, including connections to a host thatthe update removed.These updates have the following additional requirements:- URL-bound secret and egress updates must be enabled for your team. Otherwise, the request returns 403.- The session must have been created with a URL-bound secret or an egress allowlist. A session created with unrestricted egress and no URL-bound secrets can't gain either one: the update ends in FAILED with error set to requires_new_session.- Changing egress, or adding a URL-bound secret for a host the session can't reach yet, requires that the session's agent runtime supports egress updates. Sessions created before egress updates were available don't support them (409).See manifest_yaml for the format of each change.### Tracking an update1. A request that changes the session settings returns 202 with outcome set to ACCEPTED. The session status becomes SESSION_STATUS_UPDATING.2. Poll GET /v2/harness-runtime/sessions/{session_id} every 2 to 5 seconds until the status is SESSION_STATUS_READY, or SESSION_STATUS_PAUSED if the session was paused when you sent the update. The session returns to that status whether the update succeeded or failed.3. Read session.update.state: - APPLIED: the update is live. - APPLIED_RESTARTED: the update is live and the agent was restarted to apply it. - FAILED: the update did not take effect. session.update.detail explains why, and session.update.reverted is true if the previous settings were restored.Tool, URL-bound secret, and egress updates usually finish within a few seconds. Updates toenv (including the model) or plain secrets, and OAuth connection switches, restart the agentand can take up to about two minutes.If the request matches the session's current settings, it returns 200 with outcome set toUNCHANGED and nothing is applied.### VersioningEach accepted update is recorded with its own update_id and the manifest hashes before andafter the change (session.update.previous_hash and session.update.manifest_hash). When anupdate fails, the session is rolled back to its previous settings and session.update.revertedis true. Once a session's settings differ from its agent config, the session reportsconfig_drifted: true, config_diff lists the changed entries, and manifest holds thesettings the session now runs with (without secret values).### Requirements- The session status must be SESSION_STATUS_READY, SESSION_STATUS_DETACHED, or SESSION_STATUS_PAUSED. A paused session is resumed to apply the update and paused again afterwards, unless it was paused for zero balance. Any other status returns 409, including SESSION_STATUS_PROVISIONING, SESSION_STATUS_UPDATING, a session paused for zero balance, and a destroyed or failed session. A locked session returns 423.- The session must be idle: no agent turn running and no approval pending (409).- Session settings updates must be enabled for your team.- Not every agent runtime supports every section. An unsupported change returns 409.
